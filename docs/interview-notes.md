# 面试追问要点

## 为什么单体而不是微服务？

项目规模和实习场景更适合模块化单体：事务边界清晰、部署成本低、状态机/面试/提醒能在一个数据库事务中保持一致；模块边界已经通过 Controller/Service/Mapper 分层，为后续拆分保留空间。

## 如何防止 Refresh Token 重放？

Refresh Token 只放 HttpOnly Cookie，数据库保存哈希；Rotation 使用旧哈希条件更新，旧令牌再次出现即判定重放并撤销会话。

## 用户数据如何隔离？

服务层做归属校验，Mapper SQL 仍强制带 `user_id`，越权资源统一按不存在处理；Dashboard 的公司筛选也先做归属校验。

## 文件如何防伪造和穿越？

同时检查扩展名、MIME 和 PDF/DOCX 真实结构；storageKey 只允许根目录内相对路径，下载不暴露物理路径。

## 状态机为什么不直接改 status？

状态合法性、终态原因、历史、审计、乐观锁和幂等需要统一入口；直接改字段会丢失业务事实。

## Redis 宕机会怎样？

会话撤销、登录限流和 Dashboard 缓存均有数据库或内存降级；提醒数据库抢占不依赖 Redis，因此不会因 Redis 故障重复发送。

## Dashboard 为什么读状态历史？

当前状态只能回答“现在在哪里”，历史才能回答“曾经到达过哪些阶段”，也能支持跳过阶段的漏斗和周期计算。

## 技术债是什么？

ECharts 已动态拆包但总图表资源仍较大；Dashboard 当前提供平均/最小/最大周期，尚未提供中位数；生产应继续观察 MySQL 时区表和聚合查询执行计划。
